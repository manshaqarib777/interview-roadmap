## 2. Mental Model

Think of the VPC as **the office building with locked floors.** The building (the VPC, L263) is the private network — only the tenants inside may move around (L263). The floors (the subnets, L263) are the segments: the lobby (the public subnet, L263) is where the front desk (the gateway, L267) greets the visitors; the offices and the vault (the private subnets, L263) hold the work (the compute, L264) and the records (the data, L268) — not for visitors (L263). The doors (the security groups, L263) are the instance-level locks: each room opens only to the rooms that need it (L263). And the mail chute (the egress, L263) is the controlled way out: the offices reach the outside — the model provider (L278) — through the one chute (the NAT, L263) or a direct private tube (the VPC endpoint, L263). The building works because the lobby is public, the offices are locked, and the exit is controlled (L263).

## 4. How It Works — The Network, Part by Part

- **The VPC (L263).** The private network — with its own CIDR (the address range) and its own routing (L263). Every service sits inside one (L263).
- **The subnets (L263).** The segments: the public subnets — with a route to the internet gateway — hold the front door (L267); the private subnets — without it — hold the compute (L264) and the data (L268) (L263).
- **The security groups (L263).** The instance-level firewalls — allow-only, stateful (L263): the gateway's group allows 443 from the internet (L263); the compute's group allows the traffic from the gateway's group (L263).
- **The NACLs (L263).** The subnet-level firewalls — stateless, numbered rules (L263): the subnet's extra layer (L263).
- **The egress (L263).** The private resources reach the outside: the NAT gateway — the shared outbound address — for the internet calls (L263); the VPC endpoint — the private connection to the AWS services like Bedrock (L278) — never leaving the AWS network (L263).

> [!NOTE]
> **The security group is the senior tool (L263).** The NACL is the subnet's coarse layer (L263); the security group is the instance's precise layer (L263) — allow-only, stateful, and referenceable (L263). The senior design puts the precision in the security groups (L263): the gateway's group, the compute's group, the database's group — each allowing exactly the traffic it needs (L263). The NACL is the extra belt for the compliance requirements (L263).

## 8. Common Mistakes

- **Everything public (L263).** The database (L268) in a public subnet (L263) — the L313 exposure (L263).
- **The security group wide open (L263).** `0.0.0.0/0` on the database's group (L263) — the L172 baseline lost (L263).
- **The egress unplanned (L263).** No NAT, no endpoint (L263) — the model calls (L278) fail or the traffic leaks through a proxy (L263).
- **The data through the internet (L263).** The model calls (L278) and the DB traffic (L268) over the internet (L263) — the endpoint is the private path (L263).
- **The single-AZ subnets (L261).** All the subnets in one AZ (L261) — the L286 availability lost (L263).

## 9. Best Practices

- **Keep the data private** (L263) — the compute (L264) and the data (L268) in the private subnets (L263).
- **Scope the security groups** (L263) — allow-only, by the group references (L263).
- **Use the VPC endpoints** (L263) — the model calls (L278) and the AWS services never leave the network (L263).
- **Spread the subnets across the AZs** (L261) — the availability (L286).
- **Layer the NACL for the compliance** (L263) — the subnet's extra belt (L263).

## 10. Interview Questions

**Q: Walk me through a VPC.**
> A: The private network (L263). The subnets: the public — the front door, the gateway (L267); the private — the compute (L264) and the data (L268) (L263). The firewalls: the security groups — instance-level, allow-only (L263); the NACLs — subnet-level (L263). And the egress: the NAT for the internet, the VPC endpoints for the AWS calls (L278) (L263).

**Q: Why keep the data in the private subnets?**
> A: Because it's the L172 baseline (L172): the data (L268) must not be reachable from the internet (L263). The private subnets have no internet route (L263); the only path in is through the front door (L267) and its security group (L263). The exposure is the network's most common breach (L263).

**Q: How does the private compute reach the model?**
> A: Two ways (L263). Through the NAT gateway — the outbound address — for the internet calls (L263); or through a VPC endpoint — the private connection to Bedrock (L278) — which never leaves the AWS network (L263). The endpoint is the senior answer: private, fast, and auditable (L263).

**Q: What's the difference between a security group and a NACL?**
> A: The scale and the state (L263). The security group is instance-level, allow-only, and stateful (L263); the NACL is subnet-level, has allow and deny rules, and is stateless (L263). The security group is the precision tool (L263); the NACL is the subnet's extra belt (L263).

## 13. Code Example — The Network, Declared

```js

// THE VPC (L263) — the private network with its own CIDR (L263).
const vpc = { cidr: '10.0.0.0/16' };

// THE SUBNETS (L263) — the public and the private layers.
// The public: the front door (L267). The private: the work (L264, L268).
const publicSubnets  = ['10.0.1.0/24', '10.0.2.0/24'];   // AZ-a, AZ-b (L261)
const privateSubnets = ['10.0.11.0/24', '10.0.12.0/24']; // AZ-a, AZ-b (L261)

// THE SECURITY GROUPS (L263) — allow-only, by reference (L263).
const gatewaySg = {
  ingress: [{ from: 443, to: 443, cidr: '0.0.0.0/0' }],      // the HTTPS (L263)
  egress:  [{ from: 0, to: 65535, cidr: '10.0.0.0/16' }],    // the internal (L263)
};
const dataSg = {
  ingress: [{ from: 5432, to: 5432, group: gatewaySg }],      // the gateway only (L263)
  egress:  [],                                                // no outbound (L263)
};

// THE EGRESS (L263) — the model calls never leave the network (L278).
const bedrockEndpoint = { service: 'bedrock', private: true }; // the VPC endpoint (L263)
```
