## 1. One-Line Definition

**Route 53 is the DNS and the routing — the traffic's front door (L273) — the records (the name to the address: the A, the AAAA, the CNAME, L273), the health checks (the origin's pulse: the endpoint, the CloudWatch alarm, L273), and the routing policies (the latency-based to the nearest region, the weighted for the canaries L303, the failover for the DR L286, L273) — the domain resolves to the edge (L272) or the region (L261), and the traffic routes to the healthy (L273).**

The one-sentence interview answer: *"Route 53 is AWS's DNS and traffic routing (L273). The records: the name to the address — the A record for the IPv4, the AAAA for the IPv6, the CNAME for the alias to another name (L273); the alias records point the domain at the AWS resources — the CloudFront distribution (L272), the load balancer (L271), the API Gateway (L267) (L273). The health checks: the origin's pulse — the endpoint check or the CloudWatch alarm (L273) — the record routes only to the healthy (L273). The routing policies: the latency-based — the users go to the nearest region (L261); the weighted — the percentage to each target, for the canaries (L303); the failover — the primary to the standby, for the DR (L286) (L273). The AI shape: `app.example.com` resolves to the CloudFront edge (L272) for the frontend; `api.example.com` resolves to the API Gateway (L267) with the health check (L273); and the failover policy (L273) routes the traffic to the standby region (L286) when the primary fails (L273). The traffic's front door (L273)."*

## 4. How It Works — The Traffic, Part by Part

- **The records (L273).** The name to the address (L273): the A (the IPv4), the AAAA (the IPv6), the CNAME (the name to another name), and the alias (the name to the AWS resource) (L273). The alias is the senior tool: the domain → the CloudFront (L272), the load balancer (L271), the API Gateway (L267) (L273).
- **The health checks (L273).** The origin's pulse (L273): the endpoint check — the HTTP or the TCP probe (L273); or the CloudWatch alarm (L274) (L273). The unhealthy target is dropped from the routing (L273).
- **The routing policies (L273).** The latency-based — the users go to the nearest region (L261); the weighted — the percentage to each target, for the canaries (L303) and the blue/green (L303); the failover — the primary to the standby, for the DR (L286) (L273).
- **The multi-region routing (L286).** The primary region serves (L261); the health check (L273) watches it; the failover (L273) sends the traffic to the standby (L286) — the RTO (L374) is the DNS's (L273).

> [!NOTE]
> **The record answers "where"; the policy answers "which" (L273).** The record (L273) is the static mapping — the name to the address (L273). The policy (L273) is the dynamic choice — which target gets the traffic, by the latency (L261), the weight (L303), or the health (L273). The senior answer separates them (L273): *"the alias points at the load balancer, and the failover policy routes around it when the health check fails"* (L273).

## 9. Best Practices

- **Build the failover for the DR** (L286) — the primary to the standby (L273).
- **Keep the TTLs short** (L273) — the failover (L273) and the propagation (L273) fast.
