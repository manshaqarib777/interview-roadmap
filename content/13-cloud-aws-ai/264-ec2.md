## 1. One-Line Definition

**EC2 is the baseline compute (L264) — the virtual servers: the instance types (the CPU, memory, and GPU shapes, L264), the AMI (the machine image, L264), the storage (the EBS volumes, L264), and the placement (the AZ spread, L261) — with the managed trade (the Lambda L266 and the ECS L271 take the servers away, L264) — and the AI shape: the GPU instances (L264) for the training (L365), the managed options for the serving (L264).**

The one-sentence interview answer: *"EC2 is AWS's virtual server (L264). The shape is the instance type (L264): the CPU instances for the general work, the memory instances for the caches, the GPU instances — like the `p` and `g` families — for the training and the fine-tuning (L264, L365). The machine is defined by an AMI — the image with the OS and the software (L264) — and the storage is the EBS volumes attached to it (L264). The trade is managed vs unmanaged (L264): EC2 is the unmanaged baseline — you patch, you scale, you run the fleet (L264); Lambda (L266) takes the servers away for the request handlers (L266); ECS (L271) runs the containers without the servers (L271). The AI shape: the training and the fine-tuning (L365) want the GPU instances (L264) — the raw compute with the drivers (L264); the serving — the chat and the generation endpoints (L233) — prefers the managed options (L266, L271) unless the workload outgrows them (L284). The senior answer names the trade (L264): raw EC2 when the workload needs the machine, managed when it doesn't (L264)."*

## 2. Mental Model

Think of EC2 as **the rental workshop.** You rent the space (the instance, L264) with the equipment you choose (the instance type, L264): the workbench (the CPU), the storage racks (the memory), the heavy machinery (the GPU) for the big jobs (the training, L365). The workshop comes with the setup you specify (the AMI, L264) and the storage you attach (the EBS volumes, L264). You manage the workshop yourself (L264): the maintenance, the upgrades, the hours (L264). The alternative is the managed workshop (the Lambda, L266): you bring the task, and the facility runs it — no rental, no maintenance (L266). The AI workshop (L264) rents the heavy machinery (the GPU, L264) for the training (L365) and lets the managed facility (L266) run the daily serving (L264).

## 4. How It Works — The Compute, Part by Part

- **The instance types (L264).** The shapes: the general-purpose (the balanced CPU and memory), the compute-optimized (the CPU-heavy work), the memory-optimized (the caches), and the accelerated (the GPUs — the `p` and `g` families) (L264). The type is the workload's match (L264).
- **The AMI (L264).** The machine image — the OS and the software baked in (L264). The AMI makes the fleet reproducible (L264): the same image, the same machine (L264).
- **The storage (L264).** The EBS volumes — the network-attached disks (L264). The instance's data lives on the volume (L264); the volume is the persistence (L264).
- **The placement (L261).** The AZ spread (L261) — the instances across the AZs for the availability (L286) (L264).
- **The managed trade (L264).** The Lambda (L266) and the ECS (L271) take the servers away (L264): the request handlers (L266) and the containers (L271) run without the fleet management (L264).

> [!NOTE]
> **The managed trade is the senior question (L264).** The demo rents a server and calls it done (L264). The architect asks: *does this workload need the machine?* (L264) — the training (L365) does: the GPU, the drivers, the long-running job (L264). The serving (L233) usually doesn't: the request handler is a Lambda (L266), the container service is ECS (L271), and the servers disappear (L264). EC2 is the baseline the managed options abstract (L264) — not the default (L264).

## 5. Real Project Usage

- **A training job (L365).** The GPU instances (L264) — the `p` family (L264) — for the fine-tuning (L365), with the spot instances (L285) for the cost (L285).
- **A legacy service (L264).** The long-running process that can't be a Lambda (L264) — the stateful service on EC2 (L264).
- **A containerized backend (L271).** The ECS tasks (L271) on the EC2 launch type (L271) — the containers on the managed fleet (L271).
- **A self-managed database (L264).** The RDS alternative (L268) — the database on EC2 when the managed option doesn't fit (L264).
- **Anything AWS (L264).** The compute options (L264) — the baseline is EC2, the managed options abstract it (L264).

The through-line: **the compute is the workload's home** — the machine when the workload needs it, the managed options when it doesn't (L264).

- **The compute is a spectrum, not a default (L264).** The senior answer places the workload on the spectrum (L264): the training on the GPU instances (L264), the request handlers on the Lambda (L266), the container services on the ECS (L271) — the trade named, not avoided (L264).

## 8. Common Mistakes

- **The server as the default (L264).** EC2 for every workload (L264) — the Lambda (L266) and the ECS (L271) forgotten (L264).
- **The instance type guessed (L264).** The CPU instance for the training (L264) — the GPU (L264) is the type (L264).
- **The AMI not pinned (L264).** The mutable image (L264) — the fleet diverges (L298).
- **The data on the instance (L264).** The state on the ephemeral disk (L264) — the EBS (L264) and the S3 (L265) are the persistence (L264).
- **The single-AZ fleet (L261).** All the instances in one AZ (L261) — the availability (L286) lost.

## 9. Best Practices

- **Place the workload on the spectrum** (L264) — the GPU for the training (L365), the managed options for the serving (L266, L271).
- **Match the type to the work** (L264) — the CPU, the memory, the GPU (L264).
- **Pin the AMI** (L264) — the reproducible fleet (L298).
- **Persist outside the instance** (L264) — the EBS (L264), the S3 (L265).
- **Spread the AZs** (L261) — the availability (L286).
