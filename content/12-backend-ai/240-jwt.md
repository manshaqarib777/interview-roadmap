## 1. One-Line Definition

**JWT is the self-contained bearer credential — the header, the payload (the claims: identity, expiry, audience), and the signature (L240) — verified by the signature with no server lookup (L240), the stateless token behind the access tokens (L239) and the ID tokens (L239) of every modern API (L240).**

The one-sentence interview answer: *"JWT is the self-contained token (L240). Three parts: the header — the algorithm; the payload — the claims: the subject (who), the expiry (when it dies), the audience (who it's for) (L240); and the signature — the header and the payload signed with the server's secret or key (L240). The verification: verify the signature (L240) — the token wasn't forged; check the expiry (L240) — it isn't dead; check the audience (L240) — it's for this API. The value: the token is self-contained (L240) — the identity and the expiry ride in the token, so the verification needs no server lookup (L240): stateless, fast (L151). The trade: the token can't be revoked until it expires (L240) — so the expiries are short (L240) and the refresh token (L239) renews them (L239). Every modern API's access token (L239) and ID token (L239) is a JWT (L240)."*

## 2. Mental Model

Think of the JWT as **a stamped, signed passport.** The passport (the token, L240) carries the traveler's identity (the claims, L240), the issue and expiry dates (L240), and the destination (the audience, L240). The border guard (the API's verification, L240) checks: the seal is authentic (the signature, L240), the passport isn't expired (the expiry, L240), and the destination matches (the audience, L240). The guard doesn't call the home country (no server lookup, L240) — the passport is self-contained (L240). The trade: a stolen passport works until it expires (L240) — so passports are short-lived (L240) and renewed (the refresh, L239).

The mental model is **the stamped passport**: self-contained, verified by its seal, short-lived (L240).

## 4. How It Works — The Parts, the Claims, the Verification

- **The parts (L240).** The header — the signing algorithm (L240); the payload — the claims (L240); the signature — the header and the payload signed with the secret or the private key (L240).
- **The claims (L240).** The token's statements: the **subject** (who — the user or the service, L237), the **expiry** (when it dies, L240), the **audience** (who it's for, L240), the **issuer** (who signed it, L240), and the **scopes** (what it may do, L238).
- **The verification (L240).** The API verifies: the signature (L240) — not forged; the expiry (L240) — not dead; the audience (L240) — for this API; and the scopes (L238) — for this operation. Then the claims are trusted (L240).
- **The stateless value (L240).** The token is self-contained (L240): the identity and the expiry ride in the token (L240) — the verification needs no server lookup (L240): stateless and fast (L151).
- **The trade (L240).** A stolen token works until the expiry (L240) — so the expiries are short (L240), the refresh token (L239) renews them (L239), and the revocation happens at the refresh (L239).

> [!NOTE]
> **The verification is the trust — decoding is not verifying (L240).** The demo mistake: decode the token (base64 — readable by anyone) and trust the payload (L240). The senior path: *verify* the signature (L240) — the token was signed by the trusted key (L240) — then check the expiry (L240) and the audience (L240). A decoded-but-unverified token is a forged token accepted (L240). The verification path is the trust boundary (L240) — in front of every API (L233).

## 10. Interview Questions

**Q: What is a JWT?**
> A: The self-contained bearer token (L240): the header — the signing algorithm; the payload — the claims: the subject (who), the expiry, the audience (L240); and the signature — the header and the payload signed with the key (L240). The verification: the signature (L240), the expiry (L240), the audience (L240). The value: self-contained (L240) — the identity rides in the token, no server lookup (L240).

**Q: How do you verify a JWT?**
> A: The verification path (L240): the signature — is it signed by the trusted key (L240)? The expiry — is it alive (L240)? The audience — is it for this API (L240)? And the scopes — may it do this (L238)? Decoding is not verifying (L240) — the payload is readable by anyone, so the signature is the trust (L240).

**Q: Why are JWTs stateless?**
> A: Because the token is self-contained (L240). The identity and the expiry ride in the claims (L240) — the verification needs no server-side session lookup (L240). The API verifies the signature and trusts the claims (L240) — stateless and horizontally scalable (L252). The session store (L237) is unnecessary (L240).

**Q: What's the trade-off?**
> A: The revocation (L240). A stateless token can't be revoked until it expires (L240) — a stolen token works until the expiry (L240). So the senior design keeps the expiries short (L240) and uses the refresh token (L239) for the renewal (L239): the access token dies quickly, and the revocation happens at the refresh (L239). The short expiry is the security (L240).

## 13. Code Example — The Verification Path

```js
// JWT: the verification path — signature, expiry, audience (L240).
export async function verifyToken(token) {
  // 1 · THE SIGNATURE (L240) — the seal: signed by the trusted key?
  const payload = verifyJwt(token, {                                // the signature (L240)
    algorithms: ['RS256'],                    // the strong algorithms (L240)
  });

  // 2 · THE EXPIRY (L240) — is it alive? (the library checks `exp`).
  if (Date.now() / 1000 > payload.exp) {
    throw new TokenExpiredError();            // the dead token (L240)
  }

  // 3 · THE AUDIENCE (L240) — is it for THIS API?
  if (!payload.aud.includes(API_AUDIENCE)) {
    throw new TokenAudienceError();           // the wrong destination (L240)
  }

  // 4 · THE SCOPES (L238) — may it do this operation?
  if (!payload.scopes?.includes(requiredScope)) {
    throw new TokenScopeError();              // the fine print (L238)
  }

  return payload;                             // the claims are trusted (L240)
}
```
