## 1. One-Line Definition

**Amazon SQS is the managed message queue (L246) — the standard queue (best-effort ordering, high throughput, L246) and the FIFO queue (strict order, exactly-once groups, L246), with the visibility timeout (L245), the at-least-once delivery (L255) and the idempotent consumers (L255), and the DLQ (L232) — the managed belt behind the serverless AI workloads (L283).**

## 2. Mental Model

Think of SQS as **a managed conveyor belt with two modes and a repair bin.** The belt's default mode (the standard queue, L246) is fast but not strictly ordered — the orders might arrive slightly out of sequence (best-effort, L246); it's fine for the independent jobs (L245). The strict mode (the FIFO queue, L246) guarantees the order — order #2 never overtakes #1 — for the dependent jobs (L245), at the cost of speed (L246). The belt marks an order in-progress when a worker picks it (the visibility timeout, L245); if the worker drops it, the order returns (the redelivery, L255). The orders that keep failing go to the repair bin (the DLQ, L232), where the supervisor (the alert, L208) reviews them. The belt is managed — you don't build it, you just use it (L246).

## 4. How It Works — The Types, the Delivery, the DLQ

- **The standard queue (L246).** Best-effort ordering, high throughput, at-least-once (L246): the default for the independent work (L245). The standard queue may deliver out of order and more than once (L246) — the consumers are idempotent (L255).
- **The FIFO queue (L246).** Strict order per message group, exactly-once processing (L246): for the dependent work (L245), at the throughput's cost (L246). The FIFO's message group ID is the ordering key (L246).
- **The delivery (L245, L255).** The visibility timeout (L245): the in-flight message's clock — the un-acked message returns (L245). The at-least-once (L255) and the idempotent consumers (L255).
- **The DLQ (L232).** The redrive policy (L246): the poison messages move to the DLQ (L232) after the max receives (L246) — with the alert (L208) and the replay (L245).
- **The polling (L246).** The long polling (L246) — the worker's receive waits for the messages (L246), keeping the Lambda (L266) and the worker (L222) efficient (L283).

> [!NOTE]
> **The FIFO's exactly-once is per message group — and the consumers still need the idempotency (L246, L255).** The FIFO queue (L246) guarantees the strict order and the exactly-once processing *per message group* (L246). But the consumer's failure window — the process crashes after the work, before the delete (L245) — redelivers the message (L255). The senior design keeps the consumers idempotent (L255) even on the FIFO (L246): the queue's guarantees reduce the duplicates, the consumer's idempotency absorbs the rest (L255).

**Q: Standard or FIFO?**
> A: The work's dependency decides (L246). The independent work — the embedding jobs, the parallel calls (L181) — the standard queue (L246): high throughput, best-effort (L246). **Q: How does the visibility timeout work?**
> A: The in-flight message's clock (L245). When the worker receives a message, the visibility timeout starts (L245): if the worker doesn't delete the message in time (the ack, L245) — a crash — the message becomes visible again and is redelivered (L245). The timeout is sized to the job's duration (L246) — too short, the slow job's message returns mid-work (L245).

**Q: How do you handle failures?**
> A: The retry and the DLQ (L232). The message's receive count grows with each redelivery (L246); the redrive policy (L246) moves the message to the DLQ after the max receives (L246). The alert (L208) tells the humans, and the replay path (L245) re-runs the fixed message (L232). The DLQ is the queue's failure catcher (L246).

## 13. Code Example — The SQS Pattern

```js
// Amazon SQS: send, receive, DLQ (L246, L283).
import { SQSClient, SendMessageCommand, ReceiveMessageCommand, DeleteMessageCommand } from '@aws-sdk/client-sqs';

const sqs = new SQSClient({ region: 'us-east-1' });

// THE PRODUCER (L222) — the enqueue (L246).
await sqs.send(new SendMessageCommand({
  QueueUrl: process.env.AI_JOBS_QUEUE,
  MessageBody: JSON.stringify(job),
  // FIFO: MessageGroupId: job.tenant,          // the ordering key (L246)
  // FIFO: MessageDeduplicationId: job.id,      // the dedupe (L246)
}));

// THE CONSUMER (L222) — the long-polling worker (L246, L283).
async function worker() {
  const { Messages } = await sqs.send(new ReceiveMessageCommand({
    QueueUrl: process.env.AI_JOBS_QUEUE,
    MaxNumberOfMessages: 10,
    WaitTimeSeconds: 20,                        // the LONG polling (L246)
    VisibilityTimeout: 300,                     // the in-flight clock (L245)
  }));

  for (const msg of Messages ?? []) {
    try {
      if (await alreadyProcessed(msg.MessageId)) {         // the idempotency (L255)
        await sqs.send(new DeleteMessageCommand({ QueueUrl, ReceiptHandle: msg.ReceiptHandle }));
        continue;
      }
      await processJob(JSON.parse(msg.Body));   // the model call (L145)
      await sqs.send(new DeleteMessageCommand({ QueueUrl, ReceiptHandle: msg.ReceiptHandle }));  // the ack (L245)
    } catch (e) {
      // The redrive policy (L246) moves the poison to the DLQ (L232).
      await alert({ messageId: msg.MessageId, error: e });   // L208
    }
  }
}
```
